# Application implementation contract

Node 24.19.0, native node:sqlite, no runtime npm dependencies. Browser uses ES modules and guided DOM forms; maintain current COMMONS web look. This keeps application operation Node-only. The vendor engine files are immutable. The application server, engine adapter and worker, package scripts, storage, and browser forms are separate from the original engine implementation.

API prefix /api. JSON response object, errors {error,code}; errors HTTP 400/409/413/403 as applicable. api(path, body?, options?) frontend helper supplied by shell: GET when body absent; POST with JSON.stringify(body) unless options.raw, then text. csrf x-commons-token from GET /api/session {token}; cookie session from same endpoint. No request.json; strict parsing on server. Number/value helper POST /api/value {type:'number'|'boolean'|'null'|'json'|'string',text} returns {value}; server parses raw text through parseStrictJson before browser retains typed value. Never parseFloat/Number on numeric form text.

Case object {id,kind:'policy'|'discovery',title,question,description,tags:[],revision:number,input,archived:boolean,createdAt,updatedAt,latestRun:null|RunRecord,sourceNotes:{},attachments:[],notes:[]}. Each snapshot is saved as an immutable revision. Numeric input values returned by API already validated. Case initial input is blank minimal policy or valid declared binary discovery starter with zero observations. SourceNotes keyed by source id holds excerpt/locator/human assertion metadata outside engine input.

GET /api/cases?search=&kind=&archived= returns {cases:[case summaries]}; GET /api/cases/:id returns {case,history:[revisions],runs:[RunRecord],notes:[]}. POST /api/cases {kind,title,question?,description?,tags?,templateId?} returns {case}. POST /api/cases/:id/save {expectedRevision,input,title?,question?,description?,tags?,sourceNotes?} returns {case}; advanced editor uses /save-text {expectedRevision,rawInput,...metadata} strict parses rawInput on server. Return 409 on revision conflict. Investigation definition/adequacy/actions changes after observations require /fork and original preserved; ordinary save 409 MODEL_FORK_REQUIRED.

POST /api/cases/:id/archive {archived}; /duplicate {} and /fork {input?,title?} return {case}; fork has new epoch and starts zero observations, preserving original history and noting origins. POST /api/cases/:id/run {expectedRevision,idempotencyKey} returns {run,case}. input.asOf captured in explicit policy form before save; don't replace on run. RunRecord {id,caseId,revision,input,receiptText,receipt,result,digest,createdAt,current:boolean}. POST /api/cases/:id/note {text,runId?} returns {note}; notes separate from verdict.

GET /api/templates {templates:[{id,name,description,synthetic,kind,input,version}]}; POST /api/templates {name,description?,caseId} captures saved case revision, supporting files, and source assertion metadata.

POST /api/verify raw receipt text with optional ?expect=64lowerhex returns {verification,record}; no browser parse. GET /api/verifications {records:[]}; GET /api/runs/:id/receipt downloads exact raw receipt. GET /api/cases/:id/export downloads a validated binary .commons package; POST /api/import raw package bytes returns {case,checks,replayChecks}. GET /api/backup downloads all workspace data as a validated .commons-backup package; POST /api/restore raw package bytes atomically restores after complete validation. Legacy small JSON envelopes remain accepted. Limits: JSON/engine and binary metadata header 2,000,000 bytes, transport and canonical bundle 64MiB each, file upload 10MiB and workspace total 250MiB, count 200. The canonical bundle limit counts base64 file content, so a full storage workspace can exceed backup limits; exports refuse explicitly. POST /api/cases/:id/attachment?name=&type= raw bytes returns {attachment,source,case}; stored content projection source includes fileSha256, name, mediaType and app file ID; canonical source digest separately. GET /api/attachments/:id downloads bytes, Content-Disposition attachment. Uploaded attachment adds source and revision. Source human facts remain manual typed entry.

GET /api/settings {appVersion,engine:{version,archiveSha256,mode,intact},runtime:{node,platform,arch},dataDir,counts,limits}; POST /api/format raw input JSON returns {formatted,input}.

Store class exported from app/store.mjs: constructor(dataDir); listCases(query={}); getCase(id) returns API detail; createCase(data); saveCase(id,data); archiveCase(id,bool); duplicateCase(id); forkCase(id,data); listTemplates(); saveTemplate(data); addNote(id,data); addAttachment(id,{name,type,bytes}); getAttachment(id) -> {bytes,name,type,...}; getSnapshot(id,revision) -> input; addRun(id,revision,receiptText,idempotencyKey) -> RunRecord (including current flag); findRun(idempotencyKey,caseId); getRun(id); addVerification(rawText,expected,verification); listVerifications(); exportCase(id); importCase(envelope); backup(); restore(envelope); stats(); close(). Store validates all app fields, no silent type conversions, uses engine strict parser/canonical hash for JSON input as appropriate. The server parses before Store. No engine computation in Store. Receipts/attachments/manifest imported verified against bytes before writing; independently verify receipts on server adapter if imported bundle claims replay (otherwise distinct consistency checks). Engine run is adapter function run(rawInput); verify(rawReceipt,expected); immutable hashes checked for every worker request.

Frontend module contracts: web/policy.js export renderPolicy(container,{input,onChange,api,caseId,attachments,sourceNotes,onSourceNotes,onUpload}); web/investigate.js export renderInvestigation(container,{input,onChange,api,onFork}); synchronous DOM rendering, handlers asynchronous; onChange(input) called only with valid typed field values, no engine computation browser-side. Both may import shared dom helpers web/ui.js . ui.js exports el(tag,attrs,...children), field(label,control,help?), button(label,fn,className?), input(value,fn,attrs?), select(value,choices,fn), textArea(value,fn,attrs?), valueEditor(value,asyncCallback,api), numericInput(value,callback,api,attrs?) and renderError. Keep focus/cursor on edits, do not rerender all form content per keystroke.
